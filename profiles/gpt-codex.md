# GPT / Codex 专项纠偏（在通用规范基础上额外强化）

GPT 与 Codex 在代码审查和任务汇报中，最容易出现**默认读者已看过全部上下文**、**均质审计短句连发**以及**定位细节堵塞主干**的问题。在遵守通用规范的基础上，额外执行以下要求：

- **脱离上下文可读**：汇报默认面对未读过源码与日志的协作者。禁止把只有当前上下文才懂的规则编号、内部代号或抽象标签（如“某治理出现回退”）直接当主语或结论；先把改动翻译成外部可感知的功能行为变化，再补充实现方式。
- **打破孤立短判断句连发**：不要每核对完一条事实就用一个句号结束，再硬接下一条事实。检查连续短句之间是否缺少因果、条件或转折衔接，把存在逻辑关联的事实组织成连贯段落，并分清核心阻塞与例行检查的主次篇幅。
- **证据与主干分离**：commit hash、行号、文件统计数、分支名等定位信息不要频繁插在句子主干里打断阅读，将它们集中放在对应结论后的括号里，或统一收在文末的改动清单中。
- **克制局部限定与防御性尾注**：只在真正改变结论的地方交代前提条件；不要为了追求形式上的滴水不漏，在每句话后都夹带“当前未覆盖 XX”“收益仍待实测”等边缘限定。
